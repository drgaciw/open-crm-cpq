# Account merge authorization decision

**Decision:** Account merge and candidate review are sales-operations actions. Use the dedicated Entra user app role `SalesOps.AccountMerge`, mapped by ADR-016's role converter to `ROLE_SALES_OPS_ACCOUNT_MERGE`. `Admin`, `CPQ.User`, and the existing approval roles do not grant this capability by themselves. The product owner delegated this decision on 2026-11-01.

The CRM service must enforce this role for candidate review and merge commands on every request. It must verify an authenticated human caller, enforce applicable tenant and account access, reject an authenticated caller without the role with 403, and avoid treating an HTTP 200 from candidate discovery as authorization to merge. A frontend visibility check is not a security boundary.

Before the UI is enabled, the backend and identity rollout must define and implement the candidate and merge API contracts, provision the dedicated user role in the Entra manifest and environment, and expose a reliable server-derived capability to the BFF/UI. The UI must fail closed if the capability is absent or unavailable, clearly identify survivor and source, and require explicit confirmation before submitting. The backend must independently validate both accounts, prevent self-merge, preserve references through events rather than cross-service database writes, emit `AccountsMerged`, and record the actor and audit outcome. Direct API tests must cover anonymous callers, authenticated callers without the role, authorized sales-ops callers, and wrong-tenant/account access.

**Current implementation:** CRM exposes `POST /api/v1/organizations/merge` and its service requires a delegated human JWT with `ROLE_SALES_OPS_ACCOUNT_MERGE`. A valid authorized request returns `ACCOUNT_MERGE_HOLD` (503): readiness is hard-coded false, with no production override. Tenant and account authorization and durable downstream quote and contract reconciliation are not implemented. The existence of the route or its role check does not make merging operational; see the [account merge hold runbook](../runbooks/account-merge-hold.md).

Candidate discovery and a server-derived account-merge capability are not available. The account UI does not request candidates or expose a merge action and must not infer permission from endpoint availability. Role provisioning in each identity environment must be verified before any future enablement. DRG-484 and DRG-517 own the remaining merge and duplicate-detection work.
