# Orders workspace

Signals, OnPush components and HttpClient use `/api/v1/orders` and `/api/v1/order-exceptions` through the shell's `apiResponseInterceptor`. Route the exported `ORDERS_ROUTES` at `/orders`.

The UI displays immutable accepted economics separately from fulfillment projections, execution tasks and audit history. Commands carry expectedVersion, reason and an operation key. Before sending, the UI records only the opaque key/action/version in sessionStorage, never the command body or credentials. An uncertain response or 202 keeps new mutations blocked across navigation and reload until the operation lookup confirms SUCCEEDED and the view refreshes. NOT_FOUND remains uncertain. Explicit observational reconciliation is available while an order operation is unresolved; never-received operations require operator recovery. Exception commands use the same journal. Storage failure blocks dispatch. A committed command does not imply external fulfillment completion. Conversion reuses its idempotency key while references stay unchanged. The browser does not manufacture evidence or optimistic completion.

Fulfillment forms require allocation expiry and causal allocation/shipment references. The allocation and evidence ledgers show the server's references, quantities and pending/conflicting facts. Finance preparation and actual ACKNOWLEDGED/REJECTED/UNKNOWN recording use `/finance-requests` and `/finance-acknowledgments`, retaining the selected request key. Preparation never implies invoice acknowledgment. Preexecution commercial replacement needs explicit whole-order cancellation confirmation. No-effect evidence records a provider reference/time and confirmation; it never retries automatically.

Never-received command recovery sends a new versioned command to `/operations/{originalKey}/abandon`. The original journal entry remains until a matching authoritative lookup returns ABANDONED (or SUCCEEDED) and the refreshed order version is at least the lookup version. POST response text alone cannot release the gate. An uncertain abandonment request itself remains journaled. Exception commands retain their existing conservative unresolved-operation gate.

Controls remain visible and backend authorization is mandatory; 401/403 responses give actionable guidance. A 401 exposes the gateway sign-in link `/oauth2/authorization/oms` (BFF wiring is coordinator-owned). This feature adds no auth bypass or token parsing.

Conflicting observations can be disavowed through `/evidence/{evidenceId}/adjudications` with both recovery and evidence permissions, a real authority reference/time, reason and explicit confirmation. Only current-order CONFLICT observations absent from `/evidence-adjudications` are selectable. The append-only dispositions remain separate from the original ledger; neither quantities nor completion are inferred. Unknown outcomes use the existing durable-key journal. A failed disposition read blocks commands until a complete authoritative refresh.

Unit/component tests use real HttpTestingController plus the shell response interceptor; they do not prove live backend acceptance. All HTTP responses are intercepted fixtures, not live backend acceptance; this standalone browser suite is not wired into CI.
