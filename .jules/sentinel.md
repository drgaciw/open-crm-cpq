## 2024-05-10 - Fix Dynamic SQL Concatenation in Frappe Queries
**Vulnerability:** Use of string interpolation (f-strings) via `frappe.db.sql(query, $$$)` to dynamically inject table names directly into raw SQL queries within the `crm` app.
**Learning:** Even if the dynamically injected variable (like `doctype`) seems to be validated against an allowlist, string interpolation within `frappe.db.sql` violates strict static analysis rules (e.g., ast-grep `frappe.db.sql(query + where, $$$)`) and acts as an anti-pattern that could open vectors for SQL injection if validation mechanisms fail or are later modified.
**Prevention:** Always use explicit, hardcoded SQL strings, selecting the appropriate predefined query based on conditional logic instead of dynamically constructing the SQL string, while relying strictly on parameterization (e.g., `%(param)s`) for user input data.
