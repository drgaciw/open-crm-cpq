## 2024-04-11 - Fixed Dynamic Code Evaluation via new Function in List Actions
**Vulnerability:** The functions `getActionsFromScript` and `getActionsFromListScript` in `cpq_beta/frontend/src/utils/index.js` were using `new Function()` to execute dynamically provided script code. This is an RCE/XSS vulnerability, as untrusted input passed as `script` could execute within the user's browser context with full access to `window`, `document`, and potentially sensitive session tokens.
**Learning:** For safely evaluating dynamic JavaScript expressions or scripts, the `eval()` and `new Function()` methods must be avoided in frontend applications. A sandboxed interpreter like `sval` provides a secure alternative. When utilizing `sval`, the default sandbox should be maintained, and only essential safe global objects (e.g., `console`, `Math`, `JSON`, `Date`) should be whitelisted via the `import()` method. Dynamically evaluated functions can be exposed back to the host environment by appending export statements to the script execution and extracting them from `interpreter.exports`.
**Prevention:** Incorporate static analysis tooling and strict code reviews to detect and block the usage of `eval()`, `new Function()`, and similar unsafe evaluation mechanisms across frontend codebases. Enforce the use of established sandboxing libraries when dynamic script execution is an absolute requirement, coupled with thorough input validation and sanitization.
## 2024-05-25 - [HIGH] Prevent Synchronous DOM-based XSS via innerHTML on Detached Elements
**Vulnerability:** The function `htmlToText` in `cpq_beta/frontend/src/utils/index.js` was using `div.innerHTML = html` on a newly created, unattached DOM element to extract text content. Setting `innerHTML` can synchronously execute embedded payloads like `<img onerror>` even if the element is not appended to the main document body, leading to a DOM-based Cross-Site Scripting (XSS) vulnerability.
**Learning:** Parsing or sanitizing HTML strings by assigning them directly to `innerHTML` on any DOM element (attached or detached) allows synchronous execution of certain event handlers (like `onerror` on images). This creates a direct vector for DOM-based XSS.
**Prevention:** Always use `DOMParser.parseFromString(html, 'text/html')` when you need to parse HTML strings safely in the browser. It creates an inert DOM tree where scripts and event handlers are not executed, allowing safe extraction of text or further sanitization.
## 2024-05-25 - [HIGH] Fix ID Enumeration in Activities API
**Vulnerability:** The API endpoint `get_activities` sequentially called `frappe.db.exists` followed by `frappe.has_permission(..., "read", name)`. When the document did not exist, it threw `DoesNotExistError`, but when it did exist and the user lacked read permissions, it threw a `PermissionError`. This allowed an attacker to guess which IDs exist in the system based on the exception message.
**Learning:** Sequential use of existence checks and distinct permission errors creates an ID enumeration vector. Even if data isn't directly exposed, confirming an object's existence to an unauthorized user violates the principle of least privilege and can facilitate targeted attacks.
**Prevention:** Unify error messages to always return a generic `DoesNotExistError` (or "Document not found") if the record is either missing or the user is unauthorized.
