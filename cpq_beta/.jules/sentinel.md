## 2024-04-11 - Fixed Dynamic Code Evaluation via new Function in List Actions
**Vulnerability:** The functions `getActionsFromScript` and `getActionsFromListScript` in `cpq_beta/frontend/src/utils/index.js` were using `new Function()` to execute dynamically provided script code. This is an RCE/XSS vulnerability, as untrusted input passed as `script` could execute within the user's browser context with full access to `window`, `document`, and potentially sensitive session tokens.
**Learning:** For safely evaluating dynamic JavaScript expressions or scripts, the `eval()` and `new Function()` methods must be avoided in frontend applications. A sandboxed interpreter like `sval` provides a secure alternative. When utilizing `sval`, the default sandbox should be maintained, and only essential safe global objects (e.g., `console`, `Math`, `JSON`, `Date`) should be whitelisted via the `import()` method. Dynamically evaluated functions can be exposed back to the host environment by appending export statements to the script execution and extracting them from `interpreter.exports`.
**Prevention:** Incorporate static analysis tooling and strict code reviews to detect and block the usage of `eval()`, `new Function()`, and similar unsafe evaluation mechanisms across frontend codebases. Enforce the use of established sandboxing libraries when dynamic script execution is an absolute requirement, coupled with thorough input validation and sanitization.
